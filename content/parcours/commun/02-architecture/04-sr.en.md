## The status register

The status register, SR, is a 16-bit register that describes the state of the processor. Its low
byte, the CCR, holds five flags that the 68000 updates after most instructions to sum up the
result; in the next chapter, branches will use them to make their decisions.

| Flag | Is 1 when… |
|---|---|
| N | the result is negative (most significant bit at 1) |
| Z | the result is zero |
| V | the signed result is wrong, as with 127 + 1 in `.B` |
| C | the unsigned result is wrong: carry or borrow |
| X | a copy of C, for calculations over several words |

Not every instruction changes every flag:

- `MOVE`, `CLR`, `TST`, `AND`, `OR` set N and Z according to the result, clear V and C, and leave X
  alone;
- `ADD`, `SUB`, `NEG` change all five;
- `MOVEA`, `LEA`, `ADDA`, `SUBA` change none.

In the step-by-step view, a flag at 1 shows in blue.

## The high byte

For now, only one bit of the high byte matters to us: the S bit (bit 13), which puts the processor
in supervisor mode when it is 1, and in user mode when it is 0.

:::atari
TOS starts programs in user mode; in the first three chapters, 68k Trainer starts them in
supervisor mode to keep things simple, and we will come back to the two modes with TOS.
:::
:::amiga
AmigaOS starts programs in user mode, and 68k Trainer does the same. On the Amiga 500, this mode
only forbids a few instructions, such as `MOVE` to SR, `STOP` or `RTE`.
:::

The other bits will come later, with interrupts and debugging.
